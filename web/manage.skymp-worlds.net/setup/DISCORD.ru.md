# Discord для SkyMP Worlds

Документация проверена **26.10.2026**, лаунчер **0.2.0**.

Лаунчер использует публичный Application ID `1496895150322876555` для необязательного статуса активности в настольном Discord. OAuth-ссылка, токен бота и client secret в лаунчере не нужны. Настройки → Игра → Статус активности Discord: Показывать, Скрывать детали, Отключён. По умолчанию отключён. Режим стримера скрывает сведения о сервере и при включённом статусе.

## Вход на сайт и привязка аккаунта

1. В Discord Developer Portal у приложения добавьте в **OAuth2 → Redirects** точно `https://manage.skymp-worlds.net/oauth/discord-callback.php`.
2. Распакуйте новый отдельный `manage.skymp-worlds.net.zip` в корень этой субдомены. Сохраните существующие `config.php`, базу данных, `storage/` и служебные секреты.
3. В закрытом `config.php` добавьте или замените пустые значения: `MANAGE_DISCORD_CLIENT_ID` = `1496895150322876555`; `MANAGE_DISCORD_CLIENT_SECRET` = секрет из портала; `MANAGE_DISCORD_REDIRECT_URI` = адрес выше. Не помещайте секрет в лаунчер и публичные ZIP и не отправляйте его сообщением.
4. Используйте **Войти через Discord**. Для существующего аккаунта сначала войдите по паролю, затем выберите **Связанные аккаунты → Привязать Discord**. Настройки → Аккаунт в лаунчере открывают этот процесс на сайте.

Сайт сам создаёт ссылку авторизации с `identify email` и одноразовым `state` на десять минут. Скопированная ссылка без `state` отклоняется. Обмен кода выполняется только на PHP-хостинге; токены доступа не сохраняются. Игровая личность Steam остаётся прежней.

Совпадение адресов почты **не приводит к автоматической привязке**. Владелец существующего аккаунта сначала входит по паролю. Для нового Discord-аккаунта нужна подтверждённая в Discord почта. Один Discord связывается только с одним аккаунтом SkyMP.

JSON использует тот же защищённый файл аккаунтов. Для MySQL таблица `manage_oauth_accounts` создаётся при первом обращении. Если нет права CREATE, импортируйте только соответствующий раздел `CREATE TABLE IF NOT EXISTS` из `storage/mysql-schema.sql`, сохранив существующие таблицы и аккаунты. PHP нужен исходящий HTTPS с корректными CA, предпочтительно cURL, либо HTTPS streams.

Локально проверены срок действия и повторное использование state, обмен с имитацией Discord, создание и привязка аккаунтов, конфликты почты, CSRF и три языка. Настоящую авторизацию Discord и рабочую MySQL нужно проверить после настройки закрытого секрета.

Настройка относится к PHP-хостингу или указанным параметрам лаунчера. Лаунчер, игровой сервер и нативная среда публикуются отдельно. [Документация](README.md) · [Релиз лаунчера](RELEASING.md).
