# Настройка раздела разработчиков на PHP-веб-хостинге

Обновлено 25.10.2026. Настройка после загрузки трёх ZIP для поддоменов.

## Где работает каждый компонент

| Компонент | Размещение |
| --- | --- |
| DEV | PHP-веб-хостинг: раздел разработчиков и приватные отчёты |
| API | PHP-веб-хостинг: запросы лаунчера и передача отчётов в DEV |
| MANAGE | PHP-веб-хостинг: существующие аккаунты и разрешения разработчика |
| Игровой сервер SkyMP | VPS: мультиплеер и игровые файлы/моды |

Используйте **панель веб-хостинга, файловый менеджер или FTP/SFTP этого хостинга**.
Для DEV/API/MANAGE не нужны SSH на VPS или Node-служба. Настройка отчётов не меняет
игровой сервер на VPS и его server-settings.json.

## 1. ZIP уже загружены

Для защищённой папки reports загрузите обновлённый ZIP DEV. Настроенные API и MANAGE можно оставить. У каждого домена отдельный корневой каталог:
config.php и assets/ находятся непосредственно в нём. Названия DEV, API и MANAGE ниже
обозначают нужный домен, а не новые подпапки основного сайта. Сохраните аккаунты,
базы данных и существующие конфиги. Изменяйте имеющиеся define, не дублируйте константы.
Новые строки добавляйте внутрь PHP-блока, до закрывающего PHP-тега, если он есть.
Всем сайтам нужны HTTPS и PHP 8.1+, API также нужна PHP-библиотека cURL.

## 2. Папка reports в корне сайта DEV

Отчёты хранятся в **папке reports прямо в корне dev.skymp-worlds.net**.
В config.php укажите __DIR__ . '/reports'. __DIR__ автоматически определяет абсолютный путь
хостинга; /dev.skymp-worlds.net/reports может быть лишь виртуальным путём FTP, а не путём PHP.
Не указывайте URL. PHP сам создаёт папки год/месяц/день/ID и должен иметь права записи
в reports. Загрузите также reports/.htaccess и reports/index.php.

Каждый файл данных защищён PHP-оболочкой и имеет расширение .php. Прямой запрос завершается
пустым ответом HTTP 404; Apache дополнительно блокирует доступ через .htaccess.
После входа разработчика скачивается исходный JSON, лог или дамп без оболочки.
PHP должен выполняться и в подпапках. Адрес https://dev.skymp-worlds.net/reports/
должен возвращать 403 или 404, а не список файлов.

Можно продолжить использовать прежний абсолютный приватный путь вне всех корней сайтов.
Сохраните старые исходные отчёты вместе с index.json и report.key там; не копируйте их
напрямую в публичную папку reports. Другие публичные каталоги хранилища запрещены.
Веб-хостинг и VPS не используют общую локальную папку.

## 3. Два разных случайных секрета

Для каждого секрета используйте минимум 32 символа, например 64 случайных шестнадцатеричных
символа из менеджера паролей. Существующие совпадающие значения сохраняйте.
Секрет входа одинаковый в DEV_SSO_SECRET на DEV и MANAGE_DEV_SSO_SECRET на MANAGE.
Отдельный секрет передачи одинаковый в DEV_CRASH_PROXY_TOKEN на DEV и API_CRASH_PROXY_TOKEN на API.
Это не Steam API key и не ключ игрового сервера. SIGN_IN_SECRET и UPLOAD_SECRET ниже —
поясняющие заполнители, а не готовые секреты.

## 4. DEV: создать или изменить config.php

В корневом каталоге dev.skymp-worlds.net при необходимости скопируйте config.php.example
в config.php и измените значения:

```php
define('DEV_PUBLIC_URL', 'https://dev.skymp-worlds.net');
define('DEV_MANAGE_PUBLIC_URL', 'https://manage.skymp-worlds.net');
define('DEV_SSO_SECRET', 'SIGN_IN_SECRET');
define('DEV_CRASH_DIRECTORY', __DIR__ . '/reports');
define('DEV_CRASH_PROXY_TOKEN', 'UPLOAD_SECRET');
```

## 5. MANAGE: изменить существующий config.php

```php
define('MANAGE_DEV_PUBLIC_URL', 'https://dev.skymp-worlds.net');
define('MANAGE_DEV_SSO_SECRET', 'SIGN_IN_SECRET');
define('MANAGE_CRASH_REPORT_ADMINS', ['YOUR_ACCOUNT_ID']);
```

Нужен внутренний ID аккаунта управления, не почта и не Steam ID. Войдите в MANAGE и откройте
https://manage.skymp-worlds.net/crash-reports.php: страница отказа в доступе покажет ваш ID.
Доступ получают только явно перечисленные аккаунты. Старые MANAGE_CRASH_DIRECTORY и
MANAGE_CRASH_PROXY_TOKEN относятся к прежнему приёмнику внутри управления. Для нового
портала используются DEV_CRASH_DIRECTORY и DEV_CRASH_PROXY_TOKEN.
MANAGE_CRASH_REPORT_ADMINS остаётся списком разрешённых аккаунтов. Сохраните настройки почты и БД.

## 6. API: изменить существующий config.php

```php
define('API_CRASH_PUBLIC_URL', 'https://dev.skymp-worlds.net');
define('API_CRASH_PROXY_TOKEN', 'UPLOAD_SECRET');
```

API_MANAGE_PUBLIC_URL остаётся https://manage.skymp-worlds.net для аккаунтов/реестра.
Лаунчер отправляет отчёты на прежний адрес https://api.skymp-worlds.net/crash-reports.php;
API пересылает их по HTTPS в https://dev.skymp-worlds.net/crash-ingest.php.
Пересборка лаунчера или игрового сервера не требуется.

## 7. Проверить вход и импорт

Откройте DEV и нажмите **Войти через аккаунт SkyMP**. Войдите через существующий разрешённый
аккаунт управления; подписанный одноразовый билет передаётся в DEV методом POST.
Сеанс действует 15 минут. Отзыв разрешения сразу запрещает новые входы, старые сеансы
завершатся максимум через 15 минут. Импортируйте report.json из экспорта лаунчера; при
необходимости отдельно выберите crash.dmp и подтвердите согласие. Повтор не создаёт дубликат.
Проверьте статусы, скачивание и выход. Обычные аккаунты управления отчётов не видят.

При незавершённой настройке DEV отдельно показывает отсутствующие параметры: config.php, секрет входа, адреса сайтов или хранилище. Проверки доступны и после настройки по login.php?setup=1. Они не проверяют совпадение секретов на других доменах: соответствующие пары должны быть одинаковыми.
При отказе MANAGE проверьте ID аккаунта. При недействительном входе проверьте совпадение
SSO-секретов, HTTPS-адреса, cookies и приватное хранилище. При ошибке загрузки проверьте
секреты передачи, API_CRASH_PUBLIC_URL и cURL. Не включайте секреты в диагностические сообщения.

## 8. Хранение, лимиты и обслуживание без SSH

Время получения в UTC определяет reports/год/месяц/день/ID. Защищённые файлы стандартной папки называются index.json.php, report.key.php, report.json.php, contact.json.php, logs/*.log.php и attachments/crash.dmp.php. При скачивании PHP-оболочка удаляется. Для альтернативного приватного пути вне корня сайта сохраняется прежний исходный формат. Сайт читает только
выбранные загруженные файлы, а не путь на вашем ПК. В лаунчере отчёт и дамп разрешаются
отдельно. Запись дампа включается **до** запуска игры, а не после завершения процесса.

Основной отчёт — до 1 МиБ; дамп — до 128 МиБ и не выше меньшего лимита хостинга.
При необходимости измените PHP-параметры для API и DEV в панели провайдера. Необязательный
.user.ini подходит только при поддержке провайдера:

```ini
upload_max_filesize = 128M
post_max_size = 130M
max_execution_time = 180
max_input_time = 180
```

Расширения и лимиты тарифа меняет провайдер. Малый лимит дампа не мешает основному отчёту.
Apache использует приложенные .htaccess; на Nginx провайдеру нужны равнозначные запреты
для config.php, includes/ и setup/.

Используйте **Применить сроки хранения** в списке отчётов. Очистка выполняется и при
получении новых основных отчётов. Cron не обязателен для настройки. По умолчанию: 2 ГиБ,
10 000 отчётов, 20 новых отчётов от источника в час, 90 дней для отчётов и 30 для дампов.
Настройки находятся в DEV/config.php.

Если тариф поддерживает PHP-задачи, можно добавить ежедневное выполнение
скрипта tools/cleanup-crash-reports.php в корневом каталоге DEV **через панель веб-хостинга**.
Используйте поля пути и версии PHP провайдера. Это не задание для VPS. Скрипт закрыт для
URL/браузера и работает только через PHP CLI, запускаемый планировщиком хостинга.

При миграции сохраните весь прежний приватный каталог с index.json и report.key: в ZIP сайтов
этих данных нет. На том же хостинге можно использовать существующий подходящий приватный путь.
Дампы анализируются локально с подходящими PDB. Реальные пути, права PHP, HTTPS и лимиты
должны быть установлены в панели провайдера.
