# Руководство для владельцев серверов

## Область применения и совместимость {#compatibility}

Это руководство описывает единый лаунчер SkyMP Worlds **0.2.0** и интерфейсы, проверенные **22.10.2026**. Можно дополнить существующий совместимый сервер SkyMP или взять за основу [форк RealHartlMax/SkyMP](https://github.com/RealHartlMax/skymp). Регистрация в лаунчере не переносит автоматически данные игроков и игровой мир.

**Гарантии совместимости нет.** Запись в списке серверов, успешно загруженный манифест или успешная сборка ещё не доказывают, что игровая сессия работает. Должны соответствовать друг другу игровой протокол, сервер, нативный клиент, версия Skyrim, SKSE, Address Library, моды и порядок загрузки. Добавление HTTP-маршрутов не делает другой многопользовательский мод совместимым со SkyMP.

Сначала проверяй изменения на отдельной тестовой установке. До перехода сохрани конфигурацию сервера, данные мира, учётные записи и ключи. Примеры содержат заметные заглушки; размеры файлов, CRC32 и SHA-256 нужно вычислять по собственным реальным файлам.

## Как взаимодействуют службы {#architecture}

| Компонент | Адрес / протокол | Назначение |
| --- | --- | --- |
| Центральный список | `https://api.skymp-worlds.net/list.php` | Поиск серверов; адрес задан в лаунчере |
| Кабинет владельца | `https://manage.skymp-worlds.net/` | Регистрация серверов, метаданные и закрытые ключи |
| Мастер авторизации | `https://api.skymp-worlds.net` | Вход, heartbeat и игровые сессии |
| Твой игровой сервер | Публичный адрес и UDP-порт, например `7777` | Непосредственное игровое соединение |
| Твой файловый сервер | Публичный базовый HTTP(S)-адрес, например `https://files.example.org/` | Манифест модов и загрузка файлов |
| Каталог клиента | Полный URL файла `catalog.json` | Выбор подходящего нативного клиента и SKSE |

Игровой адрес, файловый сервер и мастер — разные назначения. `resourceUrl` обозначает базовый адрес файлового сервера, а не URL маршрута манифеста. Напротив, `runtimeSource` — полный URL каталога или манифеста клиента. Лаунчер подготавливает файлы, затем запускает загрузчик SKSE из выбранной папки игры.

## Путь A: Использовать указанный форк {#fork}

1. Используй [форк RealHartlMax](https://github.com/RealHartlMax/skymp). Проверь выбранный коммит или конкретный выпуск: произвольный пакет из upstream не обязательно содержит те же расширения для лаунчера.
2. Для самостоятельной сборки следуй [инструкции CMake](https://github.com/RealHartlMax/skymp/blob/main/docs/docs_cmake_workflow.md) и [CONTRIBUTING.md](https://github.com/RealHartlMax/skymp/blob/main/CONTRIBUTING.md) в форке. Заменяй работающую установку только после резервного копирования и тестирования.
3. Собранный сервер обычно находится в `build/dist/server`, клиент Windows — в `build/dist/client`. Готовые серверные пакеты запускаются через `launch_server.bat` или `launch_server.sh`. Требования к среде выполнения и первоначальная настройка описаны в [серверном руководстве форка](https://github.com/RealHartlMax/skymp/blob/main/docs/docs_running_a_server.md).
4. Предоставь собственные мастер-файлы Skyrim / DLC в настроенном `dataDir`. Серверный пакет не заменяет собственную установленную игру. Сохрани существующий совместимый порядок загрузки.
5. Зарегистрируй сервер, добавь [настройки соединения](#configuration), опубликуй моды и подходящий клиентский пакет, затем выполни [проверки](#validation).

Создай отдельную копию исходников:

```sh
git clone https://github.com/RealHartlMax/skymp.git skymp-server-source
cd skymp-server-source
```

Клонирование ещё не собирает и не запускает сервер. Для расширения лаунчера особенно важны `skymp5-server/ts/launcherResources.ts`, его регистрация в `ui.ts` и системы мастера / входа. Опубликованные маршруты модов сверены с локальным кодом; это не проверяет твои собственные бинарные файлы. Ссылка на репозиторий не публикует автоматически локальные изменения клиента, которые ещё не отправлены в него.

## Путь B: Подключить существующий сервер {#existing}

Дополняй текущий сервер целенаправленно. Единый лаунчер не меняет логику твоего игрового режима или формат базы данных. Другая реализация может потребовать дополнительных изменений.

| Требование | Что предоставить или проверить |
| --- | --- |
| Игровой протокол | UDP-сервер, совместимый с используемым нативным клиентом SkyMP |
| Данные соединения | Публичный игровой адрес, порт, базовый URL файлов, режим входа и источник клиента |
| Раздача модов | Предпочтительно [манифест v2](#manifest) и проверяемые загрузки; альтернативно ограниченный [старый контракт](#legacy) |
| Онлайн-вход | Heartbeat мастеру и серверная проверка сессий по [контракту авторизации](#authentication) |
| Среда клиента | Полные клиентские файлы, подходящие игре и серверу; [каталог](#runtime) для автоматического выбора версии |
| Подтверждение | Проверки API, загрузки и восстановления, а затем настоящие игровые тесты |

В форке новая раздача модов реализована отдельным компонентом ресурсов с явной конфигурацией. Просто скопировать файл недостаточно: HTTP-маршрутизатор должен зарегистрировать компонент, передать реальные исходные папки и порядок загрузки и правильно отвечать на ошибки. В другом серверном стеке можно реализовать тот же контракт. Названия полей JSON и правила загрузки остаются обязательными.

Работающий сервер по-прежнему можно открыть через **Прямое подключение** для первых тестов. Для публичного поиска по имени дополнительно нужны регистрация и действующий heartbeat. Публичная регистрация не подтверждает техническую совместимость.

## Учётная запись, запись сервера и публичный ID {#registration}

1. Создай обычную учётную запись в [кабинете владельца](https://manage.skymp-worlds.net/) и при необходимости подтверди почту. Демо-аккаунты не используются для игрового входа.
2. Добавь сервер с публичным адресом и игровым UDP-портом. Название и лимит игроков настраиваются только на игровом сервере; сайт получает их через heartbeat. Выбери статус `active`, когда запись должна стать публичной.
3. Открой **Лаунчер и онлайн-вход** у записи. Укажи публичный базовый адрес файлового сервера и полный URL каталога клиента. Описание, теги, страна, игровой режим и собственные ссылки сообщества являются публичными данными профиля. **Логотип и баннер размещаются на игровом сервере:** положи `logo.png` (квадрат) и `banner.png` (рекомендуется 6:1) рядом с `server-settings.json`. Поля URL изображений в веб-кабинете удалены. Обновлённый форк автоматически определяет новые, изменённые и удалённые изображения при следующем heartbeat. Максимум на PNG: 8 МиБ, 8192 пикселя по каждой стороне и 16 мегапикселей суммарно. При отсутствии или ошибке изображения используется стандартный вид. `/api/launcher/assets` возвращает публичные описания изображений, а `/api/launcher/assets/logo.png` и `/api/launcher/assets/banner.png` — файлы. Веб-шлюз проверяет размер и SHA-256 и выдаёт изображения через HTTPS, даже если файловый сервер использует HTTP. Старые URL изображений игнорируются.
4. Введите показанные значения при первоначальной настройке игрового сервера или в разделе **Настройки → Подключение лаунчера**, сохраните и корректно перезапустите сервер.
5. Сервер появится в центральном списке после первого полного heartbeat. Пустой ответ `[]` нормален, если известных записей нет. После сообщения об остановке или пяти минут без нового heartbeat известный сервер остаётся видимым как отключённый; подключение недоступно.

| Значение | Доступность | Применение |
| --- | --- | --- |
| `serverUid` | Публичное | Постоянный ID для выбора сервера и игровой сессии |
| `masterKey` в `server-settings.json` | Закрытое | Авторизация сервера перед мастером |
| `masterKey` в публичном списке | Публичное | Историческое название поля; текущий PHP-мастер помещает сюда публичный ID сервера |
| Токен входа / игровая сессия | Закрытое | Ограниченная по времени авторизация пользователя или сервера |

Никогда не публикуй закрытый ключ heartbeat в описании, тегах или загрузках. Он не должен попадать в профиль лаунчера игрока. Меняй ключ через кабинет, затем обновляй закрытую конфигурацию сервера и перезапускай его.

## Дополнить текущую конфигурацию сервера {#configuration}

В текущем форке настройки лаунчера сохраняются через **Настройки → Подключение лаунчера** в панели администратора игрового сервера. На новом сервере те же поля доступны при первоначальной настройке в браузере. Введите URL master, публичный ID сервера, приватный ключ, публичный игровой адрес и UDP-порт. Выберите **Онлайн**, включите синхронизацию модов, укажите относительную папку ресурсов и полный URL каталога. **Сохранить подключение** обновляет существующую конфигурацию, сохраняя другие настройки и данные мира. Пустое поле ключа сохраняет текущий ключ. Затем корректно перезапустите игровой сервер.

Центральная панель показывает соответствующие значения в отдельных полях. Она не редактирует файлы на удалённом игровом сервере. В других форках эту форму необходимо реализовать отдельно; примеры JSON по-прежнему описывают технический контракт.

Для учётной записи панели выберите **Забыли пароль?** на странице входа. Ссылка из письма действует 30 минут и используется один раз. После сброса войдите на сайт и в игру заново. Если отправка писем не настроена, оператор платформы должен заполнить SMTP-настройки.

Следующий JSON — **пример для объединения**, а не полная замена конфигурации. Сохрани игровой режим, пути данных, мир, прочие настройки и полный правильный порядок загрузки своего сервера. Замени публичный ID и закрытый ключ значениями своей записи.

```json
{
  "port": 7777,
  "uiPort": 8080,
  "listenHost": "0.0.0.0",
  "uiListenHost": "0.0.0.0",
  "master": "https://api.skymp-worlds.net",
  "serverUid": "srv_REPLACE_WITH_PUBLIC_ID",
  "masterKey": "REPLACE_WITH_PRIVATE_SERVER_KEY",
  "offlineMode": false,
  "launcherResources": {
    "enabled": true,
    "directory": "./client-resources",
    "runtimeSource": "https://update.skymp-worlds.net/client-runtime/catalog.json"
  }
}
```

Форк разрешает `launcherResources.directory` относительно рабочей папки серверного процесса. Запускай сервер из предусмотренной папки пакета или осознанно задай абсолютный путь. Без явных настроек раздача модов включена и использует `./client-resources`. Значение `enabled: false` отключает новый API модов.

Каталог на домене обновлений должен действительно быть загружен и подходить твоей комбинации клиента и сервера. Этот URL не обещает поддержку любой версии Skyrim. Вместо него можно предоставить собственный полный `catalog.json`. Согласуй данные манифеста сервера и кабинета; после изменения параметров загрузки нужен новый heartbeat.

## Доступность, TLS и обратный прокси {#network}

| Соединение | Типичный доступ | Проверка |
| --- | --- | --- |
| Игровой клиент → игровой сервер | `7777/UDP` или твой игровой порт | Брандмауэр, NAT и публичный игровой адрес |
| Лаунчер → файловый сервер | `443/TCP` через HTTPS или прямой HTTP-порт | Анонимный доступ к манифесту и файлам |
| Игровой сервер → мастер | Исходящий `443/TCP` | DNS, сертификат TLS и heartbeat |
| Игрок → кабинет / мастер | HTTPS | Вход, согласие и создание сессии |

PHP-хостинг может обслуживать кабинет, шлюз мастера, документацию и статические загрузки. Он не заменяет постоянно работающий нативный игровой сервер. Обычный обратный HTTP-прокси не перенаправляет игровой UDP-порт автоматически.

Для прокси используй окончательный публичный базовый URL, например `https://files.example.org/realm/`. Под этим префиксом должны быть доступны `api/launcher/manifest` и относительные маршруты файлов. Лаунчер не следует HTTP-перенаправлениям для манифестов и файлов. Указывай конечный HTTPS-адрес с подходящим именем хоста; страницы входа, Basic Auth и перенаправления не являются публичной раздачей.

URL загрузок и каталогов не должны содержать логин / пароль, параметры запроса или фрагменты. Публичный PHP-мастер отклоняет частные, loopback- и link-local-адреса, в том числе полученные через DNS. `127.0.0.1` со стороны игрока означает его собственный компьютер. Для локальной разработки используй прямое локальное подключение; не публикуй внутренние адреса в рабочем профиле. Файловые запросы лаунчера выполняются в Rust-бэкенде и не требуют разрешения CORS в браузере.

## Подготовить моды, ресурсы и порядок загрузки {#resources}

```text
server-settings.json
data/
  Skyrim.esm
  World.esp
  World.bsa
client-resources/
  Data/
    World - Textures.bsa
    Scripts/WorldClient.pex
    meshes/World/sword.nif
    textures/World/sword.dds
    SKSE/Plugins/World.ini
```

Форк автоматически включает собственные плагины из `loadOrder` и соответствующие архивы `NAME.bsa` или `NAME - *.bsa` из `dataDir`. Дополнительные клиентские файлы размещай под `client-resources/Data/` с окончательной структурой папок. Это не раздаёт автоматически серверные скрипты из `data/scripts/` как клиентские.

Все дополнительные `.esm`, `.esp` и `.esl` должны входить в фактический порядок загрузки сервера. Если плагин есть и в папке данных, и в папке ресурсов, обе копии должны совпадать. Плагины и BSA-архивы лежат непосредственно в `Data/`; текстуры, модели и скрипты сохраняют подпапки. После изменения порядка загрузки перезапускай сервер. Индекс ресурсов использует короткий кэш метаданных примерно на две секунды.

| `kind` | Допустимое содержимое пакета модов |
| --- | --- |
| `mod` | `.esm`, `.esp`, `.esl` |
| `archive` | `.bsa` |
| `script` | Скомпилированные `.pex` под `Data/Scripts/` |
| `asset` | Поддерживаемые модели, текстуры, анимации, звук, интерфейс, языковые файлы и изображения |
| `config` | Пассивные `.ini`, `.json`, `.xml`, `.txt`, `.toml`, `.yaml`, `.yml` |

Нативные DLL и JavaScript относятся к отдельному клиентскому пакету. Защищённые файлы платформы и входа, мастер-файлы Bethesda и файлы Creation Club не раздаются как моды. Отклоняются выход за пределы пути, символьные ссылки / junction, имена устройств Windows, двоеточия, конечные точки / пробелы и пути, различающиеся только регистром. Новый API модов ограничивает целевой путь 240 байтами UTF-8.

ZIP / 7z / FOMOD не распаковываются и не устанавливаются интерактивно у игрока. Самостоятельно подготовь нужный набор модов и публикуй только необходимые файлы, предназначенные для распространения. Файлы Skyrim / DLC должны происходить из подходящей установленной игры самого игрока.

## Манифест v2: Контракт для своей реализации {#manifest}

`GET <resourceUrl>/api/launcher/manifest` возвращает JSON без входа владельца, где `version` — **строка `"2"`**. Числа и контрольные суммы следующего примера показывают структуру и не относятся к реальному игровому выпуску. Сервер обязан вычислить их из настоящих файлов.

```json
{
  "version": "2",
  "revision": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "generatedAt": "2026-10-21T12:00:00.000Z",
  "totalSize": 12345,
  "loadOrder": ["Skyrim.esm", "World.esp"],
  "requiredLocalFiles": [
    { "filename": "Skyrim.esm", "size": 249753412, "crc32": 123456789 }
  ],
  "runtimeSource": "https://update.skymp-worlds.net/client-runtime/catalog.json",
  "resources": [
    {
      "name": "World.esp",
      "path": "Data/World.esp",
      "kind": "mod",
      "size": 12345,
      "hash": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "downloadPath": "api/launcher/files/1111111111111111111111111111111111111111111111111111111111111111"
    }
  ]
}
```

| Поле | Значение |
| --- | --- |
| `loadOrder` | Непустой упорядоченный список плагинов; не выводи имена из папок |
| `requiredLocalFiles` | Локальные требования Bethesda / Creation Club с именем, размером в байтах и CRC32; без URL загрузки |
| `resources[].path` | Уникальный путь назначения относительно папки игры, начинающийся с `Data/` |
| `name` | Отображаемое имя файла; может повторяться в разных папках ресурсов |
| `size` | Точное число байтов как число JSON |
| `hash` | `sha256:` и 64 шестнадцатеричных символа хэша реального содержимого |
| `downloadPath` | Относительный маршрут `api/launcher/files/` с непрозрачным шестнадцатеричным ID из 64 символов |
| `totalSize` | Общий размер ресурсов модов без отдельного клиентского пакета |
| `revision`, `generatedAt` | Идентификатор публикации и время создания |
| `runtimeSource` | Необязательная полная ссылка на каталог / манифест клиента |

Генератор должен проверять разрешённые исходные корни, исключать ссылки, нормализовать целевые пути по правилам Windows, находить дубликаты и вычислять размер / SHA-256 по прочитанному содержимому. CRC32 применяется к локальным требованиям игры и не заменяет SHA-256 при загрузке. Не возвращай противоречивые метаданные, если файлы исчезают или изменяются во время публикации. Ошибка лучше неполного успешного списка.

Текущие ограничения: не более **10 000 файлов модов**, **8 GiB на файл**, **64 GiB на пакет модов**; размер JSON-манифеста в лаунчере ограничен **8 MiB**. Своя реализация должна соблюдать те же ограничения и защищённые целевые пути.

## Маршруты загрузки и ответы HTTP {#downloads}

`GET` или `HEAD <resourceUrl>/api/launcher/files/<id>` должен отдавать файл, указанный в манифесте. ID ресурса обозначает разрешённый файл; нельзя трактовать его как произвольный путь файловой системы. Отдельный файловый хост допустим, если манифест и все относительные маршруты доступны под его базовым адресом.

| Ответ | Поведение форка / значение |
| --- | --- |
| `200` | Полный файл и правильный `Content-Length`; у `HEAD` нет тела ответа |
| `206` | Поддерживаемый одиночный диапазон байтов с `Content-Range` |
| `304` | `If-None-Match` соответствует `ETag` |
| `400` | Неверный ID ресурса |
| `404` | API отключён или ID старой ревизии больше нет |
| `409` | Файл изменился после индексации; запроси манифест заново |
| `416` | Неверный диапазон байтов |
| `503` | Публикация неполная, нечитаемая или противоречивая |

Форк также отправляет `X-Resource-Hash`, `ETag` и `Accept-Ranges: bytes`. Неизменяемые ID файлов можно кэшировать надолго; манифест должен оставаться актуальным. Лаунчер проверяет размер и SHA-256 загруженных данных независимо от HTTP-заголовков. Ему нужны полные загрузки; поддержка HTTP Range не обещает возобновление прерванной загрузки в этой версии лаунчера.

## Старые серверы: Прежний контракт {#legacy}

Только **HTTP 404** от `/api/launcher/manifest` разрешает переход к `/api/resources/manifest` и `/manifest.json`. Ответ `503`, неверный ответ v2 или несовпадение контрольной суммы не обходятся молчаливым переходом на старый режим.

Прежний контракт ресурсов использует `version: "1"`, плоские имена файлов и загрузки через `/api/resources/download/<name>`. Он не описывает полностью подпапки современных пакетов ресурсов. Дополнительный игровой манифест может иметь такую структуру; числа также являются заглушками:

```json
{
  "versionMajor": 1,
  "mods": [
    { "filename": "Skyrim.esm", "size": 249753412, "crc32": 123456789 }
  ],
  "loadOrder": ["Skyrim.esm"]
}
```

Без API ресурсов этот путь работает только тогда, когда все нужные файлы уже есть локально и соответствуют опубликованным размерам / CRC32. Он не исправляет прежнюю общую блокировку `.esm` и не добавляет отсутствующие загрузки собственных плагинов. Для новых интеграций и структурированных модпаков используй v2.

## Публикация клиента, SKSE и Address Library {#runtime}

EXE лаунчера не содержит DLL SkyMP / SKSE. Публикуй подходящую комбинацию клиента отдельно. `runtimeSource` может указывать на один `runtime-manifest.json` или на `catalog.json` с несколькими проверенными версиями Skyrim. Каталог выбирает точное совпадение по реальной версии файла `SkyrimSE.exe` и не устанавливает другую, предположительно более новую версию игры вместо подходящей.

Пример каталога с относительным адресом манифеста; замени пример SHA-256 хэшем точного файла манифеста:

```json
{
  "version": 2,
  "packages": [
    {
      "gameVersion": "1.7.104.0",
      "manifest": "1.7.104.0/client-release/runtime-manifest.json",
      "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
    }
  ]
}
```

Выбранный манифест клиента использует число `version: 1`, поля `gameVersion`, `skseVersion` и `files`. Каждый файл имеет `path`, `size` и SHA-256 **без** префикса `sha256:`. Полный пакет с версией требует как минимум эти основные пути; все дополнительные файлы среды, CEF и скриптов готового клиента также должны входить в пакет:

```text
Data/SKSE/Plugins/SkyrimPlatform.dll
Data/SKSE/Plugins/MpClientPlugin.dll
Data/Platform/Plugins/skymp5-client.js
Data/Platform/Distribution/RuntimeDependencies/SkyrimPlatformImpl.dll
skse64_loader.exe
skse64_1_7_104.dll
Data/SKSE/Plugins/versionlib-1-7-104-0.bin
```

Эти семь имён показывают комбинацию Skyrim `1.7.104.0` и SKSE `2.3.1`; это не полный список файлов и не общая гарантия. Другим версиям игры нужны соответствующие файлы и нативная поддержка. В проверенных версиях Address Library использует формат 1 для ветки 1.5, формат 2 для 1.6 и формат 5 для 1.7. Новая Address Library не делает автоматически совместимой старую несовместимую DLL плагина.

Создавай пакеты инструментами из **репозитория лаунчера**, а не из папки сервера. Следующие команды PowerShell предполагают готовую сборку клиента, распакованный подходящий архив SKSE и правильный файл адресов:

```powershell
node launcher/scripts/create-runtime-manifest.mjs `
  --source C:/Build/skymp/build/dist/client `
  --output C:/Publish/client-runtime/1.7.104.0/client-release `
  --game-version 1.7.104.0 `
  --skse-version 2.3.1 `
  --skse-source C:/Packages/skse64_2_03_01 `
  --address-library C:/Packages/AddressLibrary/SKSE/Plugins/versionlib-1-7-104-0.bin

node launcher/scripts/create-runtime-catalog.mjs `
  --root C:/Publish/client-runtime `
  --manifest 1.7.104.0/client-release/runtime-manifest.json
```

Выходная папка пакета должна быть новой. Повторяй `--manifest` для дополнительных версий игры; каждой версии соответствует ровно одна текущая запись каталога, всего не более 512. Параметр `--replace` служит для осознанной замены существующего каталога. Сначала полностью загрузи новые папки пакетов, а каталог переключай последним. Каталог проверяется заново; совпадающие хэши файлов позволяют использовать кэш.

Инструмент исключает личные настройки соединения, сохранённую авторизацию и файлы Bethesda, копирует соответствующие скрипты SKSE и имеющуюся документацию SKSE. Публикуй необходимые лицензии. Явно выбранный источник клиента в расширенном профиле лаунчера имеет приоритет; убери ручной выбор для автоматического предложения сервера. Локальная папка сборки не получает обновления из интернета.

Обычные целевые пути задаются относительно папки игры: `Data/Platform/Plugins` для клиентских скриптов, `Data/SKSE/Plugins` для нативных плагинов и Address Library, корень игры для SKSE. Форк читает папки плагинов из `Data/SKSE/Plugins/SkyrimPlatform.ini`; стандартное значение — `Data/Platform/Plugins;Data/Platform/PluginsDev`. Старые файлы в `Platform/Plugins` без `Data/` не используются и не управляются лаунчером автоматически.

Если `runtimeSource` отсутствует и в манифесте сервера, и в выбранном профиле, лаунчер может использовать только уже установленные клиентские файлы: автоматическое обновление клиента не предлагается. Изменения опубликованных файлов обнаруживаются по манифесту и хэшам при следующей подготовке. Заново загружаются только отсутствующие или отличающиеся файлы. Закрытые данные входа и создаваемые настройки соединения исключены из клиентских пакетов.

## Онлайн-вход и контракт сессий {#authentication}

Центральная платформа использует обычные учётные записи кабинета, явное согласие на игру и сессии, привязанные к серверу. `offlineMode` должен совпадать в сервере и профиле соединения. Переключение только лаунчера в офлайн не меняет авторизацию сервера.

| Метод и маршрут мастера | Назначение |
| --- | --- |
| `GET /api/users/login-discord?state=<64-hex>` | Открыть в браузере вход в аккаунт / игру |
| `GET /api/users/login-discord/status?state=<64-hex>` | После согласия получить токен входа и числовой ID; до согласия `401` |
| `POST /api/users/me/play/<serverUid>` | Запросить сессию для публичного ID сервера с токеном входа |
| `POST /api/servers/<privateMasterKey>` | Heartbeat сервера с `name`, `online`, `maxPlayers`, необязательными `serverUid` и `serverStatus` (`online`/`offline`) |
| `GET /api/servers/<privateMasterKey>/sessions/<session>` | Проверить сессию на игровом сервере; успешный ответ содержит `user.id` и `user.name` |
| `GET /api/servers/<serverUid>/manifest.json` | Получить публичный игровой манифест через прокси мастера |
| `GET /api/servers/<serverUid>/serverinfo` | Получить публичные свойства соединения |

`POST /api/users/me/play/...` передаёт токен входа в заголовке `Authorization`; PHP-мастер также принимает префикс `Bearer`. Ответ содержит `session`. Для heartbeat и проверки сессии закрытый ключ использует только игровой сервер. Считай соответствующие строки серверных журналов и URL конфиденциальными и удаляй ключи перед запросом поддержки.

Сессия действует только для предназначенного сервера и его текущего закрытого ключа. Истечение срока, выход из кабинета и смена ключа могут аннулировать сессии. Сервер обязан отклонять недействительные сессии. Новый мастер не должен переназначать существующие числовые игровые ID без запланированного переноса данных.

Историческое название маршрута `login-discord` у этого PHP-мастера **не означает автоматически настроенный Discord OAuth или проверку гильдии**. Дополнительные правила ролей / гильдий Discord требуют подходящей настоящей интеграции провайдера. Публичное приглашение сообщества не является провайдером входа. Отдельный совместимый мастер можно настроить для прямых подключений; центрально зарегистрированный сервер использует параметры мастера из центрального списка.

## Проверка до подключения игроков {#validation}

### Этап 1: Публичные HTTP-интерфейсы

В примерах PowerShell ниже используется `curl.exe`, чтобы не вызвать старый псевдоним PowerShell. В Linux команда называется `curl` и принимает те же параметры. Замени `files.example.org` окончательным публичным адресом.

```powershell
curl.exe --fail-with-body https://api.skymp-worlds.net/health
curl.exe --fail-with-body https://api.skymp-worlds.net/list.php
curl.exe --fail-with-body https://files.example.org/api/launcher/manifest
curl.exe --fail-with-body https://update.skymp-worlds.net/client-runtime/catalog.json
```

Ожидаются ответы JSON без страницы входа и перенаправления. Проверь публичный ID, базовый адрес файлов, режим входа, порядок загрузки и источник клиента. Закрытый ключ сервера не должен появляться в публичном списке. Загрузи хотя бы один реальный ресурс по опубликованному ID и сравни локальную контрольную сумму с `hash`:

```powershell
Get-FileHash -Algorithm SHA256 ./downloaded-file.bin
```

В Linux подходит `sha256sum ./downloaded-file.bin`. Также проверь, что неизвестные ID, изменённые файлы и неверные пути возвращают понятные ошибки и никогда не выдают произвольные файлы сервера.

### Этап 2: Подготовка без запуска игры

Выбери отдельную подходящую тестовую папку игры с `SkyrimSE.exe`. Закрой Skyrim. Открой сервер в лаунчере, затем **Параметры подключения** и **Подготовить файлы**. Это не запускает игру, но изменяет подготовленную тестовую установку. Проверь подпапки, полноту клиентских файлов, порядок загрузки и созданные настройки соединения. Повтори подготовку: корректные файлы должны браться из кэша. Затем проверь **Восстановить исходные файлы** и переключение между двумя тестовыми профилями.

Лаунчер проверяет хэши и версии перед активацией. Неверный хэш, отсутствующая версия пакета или прерванная загрузка не должны активировать неполный выпуск. [Исходники лаунчера](https://github.com/RealHartlMax/skymp-client-launcher) также содержат временные HTTP-тесты / тесты восстановления и тест с отдельной копией нативного сервера.

### Этап 3: Собственный полный игровой тест

Только теперь проведи настоящий тест Skyrim / SKSE с нужной версией: запуск, браузерный вход и согласие, проверка сессии, UDP-соединение, общий мир и повторное подключение. Дополнительные нативные плагины проверяй отдельно. Успешные файловые и API-проверки не заменяют этот тест. Зафиксируй реально проверенную ревизию сервера / клиента и модпак до публикации для игроков.

## Обновления, откат и восстановление {#operations}

Публикуй новые моды и клиентские файлы как согласованный выпуск. Синхронизируй порядок загрузки, данные сервера и клиентские ресурсы. Для обновлений клиента создавай новые неизменяемые пути пакетов, загружай все файлы и переключай каталог последним. Изменение каталога не заменяет необходимый перезапуск сервера после изменения плагинов.

Кэши лаунчера разделены по целевым серверам. Оригиналы и журнал активации находятся в `<Skyrim>/.skymp-launcher/`. Списки плагинов в профиле Skyrim и при необходимости `Skyrim.ccc` изменяются под выбранный порядок загрузки. Сохраняй журнал, пока файлы активны; не удаляй его как предполагаемое исправление. Восстановление может остановиться для защиты твоих собственных изменений управляемых файлов.

До обновлений отдельно от лаунчера сохраняй данные мира и конфигурацию сервера. Оператор центральной PHP-платформы должен совместно сохранять хранилище аккаунтов и закрытое хранилище авторизации с сопоставлением ID и ключами. Откат каталога клиента меняет только предлагаемые клиентские файлы, а не отменяет автоматически перенос серверных данных или мира.

Если ID сервера заблокирован или скомпрометирован, смени ключи, обнови закрытые настройки и перезапусти heartbeat. Для поддержки достаточно публичного ID, времени, версий лаунчера / клиента / Skyrim и очищенных ошибок. Пароли, закрытые ключи мастера и сессии нельзя отправлять в Discord.

## Диагностика конкретных ошибок {#troubleshooting}

| Симптом | Следующая проверка |
| --- | --- |
| Heartbeat возвращает `404` с `Server is not registered yet` | Старый маршрут реестра: обнови корень API, включая `api/servers/index.php` и `native-heartbeat.php`, вместе с кабинетом; сохрани закрытые настройки и данные |
| Сервер не находится по имени | Проверь статус `active`, публичный адрес, действующий закрытый ключ и свежий heartbeat |
| Новый маршрут манифеста возвращает `404` | Проверь версию форка / маршрутизатора и `enabled`; только тогда предусмотрен ограниченный старый режим |
| Манифест возвращает `503` | Проверь журнал сервера, исходные папки, ссылки, дубликаты путей и незавершённую публикацию |
| Загрузка возвращает `409` или неверный хэш | Заверши публикацию, получи новый манифест и переиндексируй реальные содержимое и размеры |
| Прокси мастера возвращает `502` | Проверь публичный URL файлов, DNS / TLS, доступность и запрет частных адресов; убери перенаправления |
| Онлайн-сессия недействительна | Не путай публичный `serverUid` с закрытым `masterKey`; проверь режим входа, смену ключей, срок и согласие |
| `/account` или маршрут входа возвращает `404` | Проверь корень API-сайта, Apache rewrite / передачу Authorization и настройки мастера |
| Файлы готовы, но игра не подключается | Проверь UDP-порт, брандмауэр / NAT, игровой протокол и реальную совместимость сервера и клиента |
| Ошибка `REL/ID.h` / Address Library | Определи сбойную DLL плагина; вместе проверь версию Skyrim, SKSE, ожидаемое имя файла и нативный формат данных |
| Новейший файл адресов есть, но ошибка остаётся | Старая DLL может искать неверный файл или не понимать новый формат; обнови DLL вместо переименования BIN |
| Клиентские файлы остаются старыми | Проверь ручной источник клиента в расширенном профиле, используемый `runtimeSource` и хэш записи каталога |
| Восстановление отказывается менять файлы | Закрой игру, сохрани сторонние изменения управляемых файлов и оставь журнал; не удаляй вслепую |

За помощью обращайся в [Discord SkyMP Worlds](https://discord.gg/NSXtNNbjuR). Устранение одной ошибки загрузки не доказывает, что все остальные нативные плагины подходят версии игры.

### Название, лимит игроков и статус сервера (24.10.2026)

Название и максимальное число игроков задаются только в панели игрового сервера. Сайт получает значения из аутентифицированного heartbeat и показывает их без редактирования. Сохранение регистрации на сайте больше не создаёт heartbeat. Сервер попадает в публичный список после первого полного heartbeat.

Heartbeat передаёт `name`, `maxPlayers` и текущее число игроков в `online`. Необязательное поле `serverStatus` принимает `online` или `offline`; текущий форк сообщает об остановке. Через **5 минут** без heartbeat известный сервер также считается отключённым. Публичный список содержит `server_status` и `last_heartbeat`. Отключённый сервер остаётся видимым, но подключение недоступно до следующего heartbeat о запуске. Открытые списки лаунчера и сайта обновляются каждые 30 секунд.

Статус доступности не связан с `offlineMode`, который управляет авторизацией игры. После изменения названия или лимита сохраните настройки и при необходимости перезапустите игровой сервер.

### Восстановление отсутствующего gamemode.js

`ENOENT ... gamemode.js` означает отсутствие файла на VPS. Восстановите собственный режим из резервной копии либо укажите существующий путь в **Редактор CFG → Общие → Файл игрового режима на сервере**, сохраните настройки и перезапустите игровой сервер. Путь задаётся относительно рабочего каталога или абсолютно. Архив сервера r4 содержит стандартный `gamemode.js` только для неизменённого стандартного сервера; не заменяйте им собственный режим. Новый обработчик сохраняет последний загруженный режим при временном исчезновении файла и продолжает загрузку после восстановления.

## Ресурсы и имя игрока в панели {#resources-player-name}

Раздел Ресурсы находит ESM, ESP и ESL непосредственно в настроенной папке данных сервера и в Data папки загрузок лаунчера. После загрузки перечитайте файлы, включите нужные плагины и упорядочьте стрелками. Новые файлы сначала отключены. Skyrim.esm должен быть первым; мастер-файлы загружаются до зависимых плагинов. Файлы из папки загрузок также должны быть в папке данных сервера. Обе копии должны совпадать.

Сохранение порядка меняет только loadOrder существующей конфигурации. Перезапустите игровой сервер для обновления активного манифеста. Лаунчер записывает plugins.txt и loadorder.txt, сохраняя оригиналы при обновлении из кеша и смене сервера. Для новой панели соберите оба backend и dashboard frontend в репозитории сервера. Сохраните конфигурацию, миры, моды и ключи.

Лаунчер передаёт отображаемое имя вместе с подтверждённым Steam ID. Оно видно в допуске/Whitelist и списке игроков. Имя игрока отдельно от имени RP-персонажа; переименование не меняет личность, допуск и профиль. Нужна соответствующая новая версия исходного кода сервера.

Необязательный вход через Discord настраивается на PHP-хостинге с закрытым client secret. Пользователь существующего аккаунта сначала входит по паролю и явно привязывает Discord через https://manage.skymp-worlds.net/account.php . Для статуса активности лаунчера нужны только публичный App ID и настольный Discord, без веб-OAuth. Проверки гильдии или ролей Discord при этом не добавляются.
